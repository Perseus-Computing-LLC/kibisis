## Findings (most severe first)

### R4-1 — R3-AB2 residual: blanking the envelope (not just flipping `is_encrypted`) re-enters the format-1 migration — **high** (file writer; same cost profile as R2-B1 / R3-AB2)
*Where:* `_vault_crypto.py:415-421` (`_format_2_artefacts`: the entry witness is the binding string inside
`encrypted_envelope_json`); `:722-729` (`_migrate_integrity` refuses a row with `is_encrypted != 1` AND a
non-empty envelope); `:730-744` (the "journal records entries, table is empty" check runs only when
`not rows`); `:805-815` (a headless format-1 chain verifies under the passphrase legacy key, but a headless
format-1 chain has no keyed element at all — `_event_hash(..., fmt=1)` is a plain hash, cf.
`tests/test_review3_ab_migration.py::_legacy_rechain`).
*Problem:* the R3 fix moved the witness from the integer column to the envelope text and added an
inconsistency check for "plaintext row with envelope". A file writer who does the R2-B1 reset and then
`UPDATE entities SET is_encrypted = 0, encrypted_envelope_json = NULL, tenant_sig = NULL` leaves no binding
string (no witness), no inconsistent row, a non-empty entity table (so the empty-table check does not run),
and a headless format-1 chain that needs no key to verify. The open succeeds, migrates, writes a head, key
check and meta MAC, reports `entries_left_unsigned: 3`, `verify_audit_chain()` is True, `is_tombstoned` of
the rejected value is False and a `remember` of it is accepted. Cost to the attacker as in R2-B1: the three
entries read as unsigned until `adopt_unsigned_entries()` (the sealed text is gone from the rows, but a file
writer keeps a copy). SECURITY.md:97-99 says the only indistinguishable reset "rewrites the journal headless
and empties the vault" — this one empties nothing: rows and `put` events stay.
*Repro:* `review4_r3fixes.py::test_attack_discriminator_is_defeated_by_blanking_the_envelope` (passes).
Controls `::test_control_tenant_sig_blank_alone_is_still_refused`,
`::test_control_journal_deleted_with_entries_kept_is_refused` pass (the sealed rows stay witnesses).
*Fix:* a keyed (salt-present) 0.1.0a5 file sealed every entry (the fixture: 6/6 `is_encrypted = 1`), so with
`kdf_salt` present refuse any row with `is_encrypted = 0` (or at least an empty, unsigned plaintext row whose
identity the journal records as `put` and never purged — generalise the `not rows` check to "every live
identity has an openable row"). Independently: a genuine a5 file has no `audit_head` table and no `format`
column (`tests/fixtures/vault-0.1.0a5-fallback.sqlite`); `_init_schema` creates them before the migration
looks, but the plain file can be inspected in `_check_plain_file_passphrase` / before `_init_schema`: a
salt-present file below format 2 that already has `audit_head` is not an a5 file. Say in SECURITY.md:97-99
that the indistinguishable reset is "headless journal + no sealed entry", not "empties the vault".

### R4-2 — R3-AB4 residual: under a legacy (V1) meta MAC a stored quorum is trusted whenever it is ≥ the default, so a file writer lowers a person's 3 to 2 and the re-sign makes it permanent — **low–medium** (file writer; pre-R2-B4 file not yet re-signed; only when the person had pinned above 2)
*Where:* `vault.py:1108-1134` (`_stored_quorum`: `if self._meta_mac_legacy and stored < DEFAULT_VERIFICATION_QUORUM: return None`);
`_vault_crypto.py:511-528` (`_verify_meta_mac` re-signs over the kept value); changes/area_a.md:226-227 "a
value at or above the default can only raise the bar and is kept and covered".
*Problem:* "can only raise the bar" is measured against the default, not against what the person pinned. A
round-1-era file stores the quorum in `vault_meta` under a V1 MAC that never covered it, so the file writer
needs no backup copy: `UPDATE vault_meta SET value='2' WHERE key='verification_quorum'` on a file pinned at
3. The next writable open (naming no quorum) adopts 2 (`verification_quorum_stored == 2`), re-signs the
full-set MAC over it, logs only the generic "stored quorum below the default is dropped" WARNING (nothing
was dropped), and a second account's review mints `verified` with two attestations instead of three. Every
later open adopts 2 in silence (it is not below the default, so no `ConfigError`).
*Repro:* `review4_r3fixes.py::test_attack_legacy_meta_mac_keeps_a_lowered_quorum_that_is_still_at_the_default`
(passes: quorum 2 adopted, `verified` on two accounts, full-set MAC over `verification_quorum = '2'`).
*Fix:* under a legacy MAC trust no stored quorum: drop it whatever its value and let the next verdict re-pin
(the person loses nothing: a verdict run under their `KIBISIS_VERIFICATION_QUORUM` restores it), or keep it
but do not re-sign it (leave `verification_quorum_stored = None` and log the kept value as "unverified, set
by …"). Reword area_a.md / SECURITY.md:82-84.

### R4-3 — R3-AB1 residual, legacy events only: a pre-fix `tombstone_lifted` for a global (`'*'`) row lifted by a write of the same `category:key` is still not reconciled — **low** (needs a pre-fix event of that exact shape; a lower-class `'*'` row only comes from a snapshot import)
*Where:* `_vault_crypto.py:650-655` (`_check_tombstones`: the metadata match runs only when
`metadata.tombstone != f"{category}:{key}"`; `tombstone_scope` is read inside that branch only).
*Problem:* `_find_tombstone`/`_tombstones_matching` match rows in the writer's scope OR `'*'`. A pre-fix lift
of a `'*'` row by a write of the same `category:key` in scope `default` journaled `(c, k, V, default)` with
`metadata.tombstone = "c:k"`, `tombstone_scope = "*"`; the equality short-circuits the metadata path, the
pop by the event's own identity misses `(c, k, V, '*')`, and the vault wedges exactly as R3-AB1 did (writable
and read-only `VaultIntegrityError: journaled tombstone(s) have no row`). New-code lifts name the row's scope
and reconcile (`::test_control_one_write_lifts_the_scoped_and_the_global_row_and_both_reconcile`).
*Repro:* `review4_r3fixes.py::test_attack_legacy_lift_event_of_a_global_row_under_the_same_key_still_wedges_the_open`
(passes; the pre-fix event is emulated the way `test_review3_ab_tombstones.py` does, through
`_record_audit_event`; the `'*'` agent-class row is planted the way a snapshot import with `origin="model"`
leaves it).
*Fix:* in the legacy branch also pop `(category, key, value_sha256, tombstone_scope)` whenever
`metadata.tombstone_scope` is present and differs from the event's scope, regardless of the name test.

### R4-4 — `import_snapshot(origin=None)` is principal, so the R3-AB3 class cap is a no-op for every caller in `src/` — **low (documented; record only)**
The cap (`_vault_snapshot.py:329-336`) binds only when the importer names a lower `origin`. `origin=None`
means "the caller vouches for a person" (as on `put`), and no caller in `src/` passes `origin`
(`import_snapshot` is library-only). An unsealed, unmanifested file with `digest_scheme: sha256` and a
`principal` tombstone therefore still plants a principal rejection that refuses the person's own next write
of that value until `kibisis-review lift` (`::test_control_default_import_origin_is_principal_so_the_cap_only_bites_when_named`,
which also shows `origin="model"` capping it at `agent`). Consistent with the documented semantics; worth one
sentence in the `import_snapshot` docstring: "pass `origin=` for a file you did not make".

## Suspected, unconfirmed
- With SQLCipher installed the plain file is converted on open; `_check_plain_file_passphrase` compares "the key
  check, or for a 0.1.0a5 file one of its sealed entries" — after the R4-1 reset there is neither. Whether
  that path then accepts any passphrase for the conversion was not tested (the tests run without SQLCipher,
  which is the file-writer model); worth a control when R4-1 is fixed.
- `import_snapshot` with `same_key` (public `digest_key_id` matches) copies `value_sha256`/`sealed_digests`
  verbatim; a forged `sealed_digests` is never verified at open (only `tombstone_mac`, recomputed by the
  importer), so a later export carries garbage that foreign vaults report as "foreign". Low; not tested.
- `_check_tombstones`' R3-AB5 class check compares against the *latest* `tombstone` event; a legitimate
  future path that lowers a row's class (none exists today) would wedge every open. Note for maintainers.
